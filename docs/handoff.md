# 공동주택 AI 감사관 (HOA-Guard) — Claude Code 핸드오프 문서

## 프로젝트 개요

아파트 관리사무소·입주자대표회의의 비리(관리비 부정지출, 수의계약 유착, 입찰 조작 등)를 줄이기 위한 **AI 기반 투명성/감사 시스템** 설계 및 프로토타입 개발.

**핵심 원칙**: AI는 의결권을 갖지 않는다. 의사결정 주체(입주자대표회의)는 그대로 유지하되, 그 위에 **강제적인 투명성/이상탐지 레이어**를 씌운다. 목표는 "정보 비대칭 해소"이지 "인간 대체"가 아니다.

현재 상태: **기획/설계 단계만 완료, 코드 없음.** 이 문서를 시작점으로 Claude Code에서 프로토타입 구현을 이어감.

---

## 시스템 구성 (5개 모듈)

### 1. 지출 이상탐지 엔진
- 관리비 지출/계약 데이터를 DB화 (업체, 단가, 계약일, 금액)
- 과거 3~5년 데이터 기반으로 이상치 탐지:
  - 시세 대비 20%+ 과다 견적
  - 동일 업체 반복 수의계약
  - 계약 쪼개기(입찰 회피 패턴)
- 플래깅 발생 시 대표회의 + 주민 앱에 **동시** 알림 (은폐 방지가 핵심 설계 목표)

### 2. 계약/입찰 비교 어시스턴트
- 견적서 업로드 → 유사 규모 단지 낙찰가 데이터와 자동 대조 리포트
- 입찰 공고문 표준화 템플릿 (특정업체 유리 조건 방지)

### 3. 투명성 아카이브 + 자동 요약
- 회의록/계약서/예결산 자동 요약, 주민 앱에 자연어로 공개
- 회계 전문용어 → 일반인 이해 가능한 언어로 변환

### 4. 장기수선계획 시뮬레이터
- 건물 노후도 + 적립금 추이 기반 10~20년 수선 시나리오 시뮬레이션
- "공사 지연 시 N년 후 비용 증가폭" 예측

### 5. 외부 연동 감사 채널
- 구청 공동주택관리 지원센터, K-apt(국토부 공동주택관리정보시스템)와 데이터 연동
- 이상탐지 발생 시 외부 신고 절차 원클릭 연결

---

## 거버넌스 요구사항 (설계 제약, 반드시 지킬 것)
- AI에게 의결권/승인권을 주는 기능은 만들지 않는다.
- 모든 이상탐지 결과는 판단 근거(대조 데이터)를 함께 제시해야 한다 — 블랙박스 판정 금지.
- 로그는 append-only 구조로 설계 (수정/삭제 이력이 남아야 함, 블록체인까지는 불필요).

## 단계별 도입/개발 우선순위
1. **1단계 (MVP)**: 지출 이상탐지 + 공개 대시보드
2. **2단계**: 입찰 비교 어시스턴트
3. **3단계**: 장기수선계획 시뮬레이터 + 외부 감사 연동

---

## Claude Code에서 이어갈 작업 (제안)

아직 기술 스택/플랫폼이 확정되지 않음. 다음 사항을 먼저 사용자와 확인 후 진행:

1. **플랫폼 결정**: 웹 대시보드(주민 열람용) vs 관리사무소 내부 도구, 또는 둘 다
2. **1단계 MVP 범위 확정**: 지출 이상탐지 엔진부터 구현할지, 프로토타입은 목업 데이터로 시작할지
3. **기술 스택**: 프론트엔드/백엔드/DB 미정 — 사용자의 기존 홈랩 환경(Synology NAS, 홈 네트워크 대시보드 작업 이력 있음)과 연동 가능성 검토 필요
4. **데이터 소스**: 실제 관리비 지출 데이터 포맷이 없으므로 초기엔 합성/목업 데이터로 이상탐지 로직 검증 필요

### 즉시 시작 가능한 작업
- 이상탐지 알고리즘 프로토타입 (통계적 이상치 탐지: 업체별 단가 분포에서 z-score 또는 IQR 기반)
- 목업 관리비 지출 데이터셋 생성 (CSV)
- 대시보드 UI 와이어프레임 (주민 공개용 요약 화면)

## 참고: 관련 법규/제도 맥락
- 공동주택관리법상 의사결정 주체는 입주자대표회의(법인 아님, 대표성만 가짐)
- 계약 체결/손해배상 등 법적 책임은 AI가 질 수 없음 — 시스템은 "의사결정 지원 + 투명성 강제" 역할로 한정
- K-apt(공동주택관리정보시스템)는 국토부 운영 공식 공시 시스템 — 3단계 외부 연동 시 참고
